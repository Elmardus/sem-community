# 2.2 cluster 1 — visibility: sessions, PV health, hints

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Show the user three things SEM already knows: each charging
session (#1024), whether the PV plant does what the forecast said (#1022),
and a short hint when something is off (#1019).

**Architecture:** No new inputs. Sessions come from the stored history,
PV health from the forecast ledger, hints from facts the coordinator
already has. Each part is inert on its own: a list, a sensor, five
switches that are off. Built whole on `feature/2.2-visibility`, one deploy
to prove.

**Tech stack:** Python (coordinator, storage, sensor, services, one
websocket command), LitElement card (`sem-ev-status-card.js`),
`dashboard/translations.json` × 16.

**Branch:** `feature/2.2-visibility`, worktree `/home/sem/sem-2.2`, off
develop `4bc96443`. Status: PLAN, nothing built. Build starts on

## Open decisions (the plan assumes the first option)

1. **Hint switches.** Five switch entities, one per category, as the issue
   asks. Or one switch "hints" with all five fixed on. Five is the issue;
   one is smaller.
2. **Session cost in the list.** Old sessions have no cost stored. Show
   them with an empty cost column, or hide cost until the first new
   session. The plan shows empty.
3. **PV health colours.** 7-day yield ÷ forecast: green ≥ 85 %, yellow
   ≥ 65 %, orange ≥ 40 %, red below. Fewer than 3 settled days → unknown.
4. **Weekly numbers.** Kept by SEM at midnight in a 14-day list (small,
   new). Or read from the recorder once a week (no new data, a heavier
   read). The plan keeps the list.

### Task C2: the engine

**Files:** new `coordinator/hints.py`, `coordinator/storage.py`
(`hints_sent`, `night_means` (14), `daily_totals` (14)), test
`tests/test_1019_hint_engine.py`.

`HintEngine.evaluate(facts, now) -> list[Hint(category, key, text_key,
params)]`. One message per event key; `sent[category] == key` blocks a
repeat; persisted so a restart does not repeat.

| category | fires when | key | text |
|---|---|---|---|
| silent_input | an input dark ≥ 15 min (`UNAVAILABLE_REPAIR_THRESHOLD_S`); again when it returns | entity + start | "Solar power stopped sending 17 min ago." |
| night_load | at 07:00, mean home W 01–05 h > 1.5 × 7-night median and > 300 W | date | "The house used 620 W all night, usually 210 W." |
| grid_rise | at 20:00, import kWh > 1.5 × 7-day median while solar within ±25 % of its median | date | "Grid use rose to 9.1 kWh (usually 4.2) with the same sun." |
| cheap_now | price level turns cheap, a car is plugged in and not charging | window start | "Power is cheap until 06:00. The car is plugged in and not charging." |
| weekly_summary | Sunday 19:00 | ISO week | "This week: 142 kWh solar · 71 % self-use · 38 kWh from the grid · 24 kWh into the car · 12.40 CHF." |

- [ ] Test per row: fires once, again on a new key, never when the switch
      is off; a restart with `hints_sent` stored stays quiet.
- [ ] Commit `feat(#1019): hint engine`.
