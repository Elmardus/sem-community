> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** SEM recognises six more brands and can write a battery setpoint two more ways — built from each integration's own source, shipped inert, verified by the reporters who own the hardware.

**Architecture:** Three mechanisms already exist and this branch only feeds them. (1) A brand is a **data row** in `_BRAND_HINTS` + one entry in `_EV_CHARGER_PLATFORMS` + one row in the hardware matrix (#814, #816). (2) The **roster** (#915) mines an integration's vocabulary offline and proposes roles at runtime as an intersection with the local entity registry. (3) The **generic battery adapter** has ONE setpoint write path (`base.py:_write_force_discharge`). Nothing here acts on a house that does not have the brand; the default setpoint model stays `signed`.

**Tech Stack:** Python 3.13/3.14, Home Assistant custom integration, pytest via `~/bin/semtest` (CI layout). Branch `feature/2.2` in the worktree `/home/sem/sem-2.2` — never in the main checkout (the 21:00 cut needs develop there).

def _discover_wallbox_mqtt(entities) -> Dict[str, str]:
    """(#984) Identity: power AND an energy counter AND the current control,
    all wallbox-named — a plug publishing power over mqtt is not a charger."""

    if not {"ev_charging_power_sensor", "ev_current_control_entity"} <= result.keys():
        return {}
    if not ({"ev_total_energy_sensor", "ev_session_energy_sensor"} & result.keys()):
        return {}
    return result
